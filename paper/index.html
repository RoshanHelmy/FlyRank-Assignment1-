Content Opportunity Scoring for SEO Action Prioritization

A measured, decision-support baseline and modeling study for prioritizing content pages for human SEO review.

Capstone research artifact · 2026

Abstract

This study asks whether observable content-performance signals can support a ranked queue for prioritizing SEO content actions. The analysis uses the FlyRank ML Internship dataset and focuses on measurable signals including search impressions, click-through rate (CTR), average search position, and content characteristics. A rule-based baseline was constructed first and a machine-learning modeling workflow was then evaluated using an explicit validation design and leakage checks. The observed results show that impressions, CTR, and search position provide useful directional signals for identifying pages that may deserve human review, while the analysis does not establish that the resulting ranking will cause future traffic or ranking improvements. The final output is therefore framed as a decision-support queue rather than an autonomous SEO system.

1. Introduction / Problem Statement

SEO teams may have many content pages competing for limited editorial and optimization capacity. A practical question is therefore not simply which pages perform well, but which pages appear to have signals that justify further investigation.

The research question for this project is:

Can observable content-performance signals be used to rank pages for human review and content-action prioritization?

The intended decision is narrow: help a human reviewer decide which pages should be inspected first. The system is not intended to automatically rewrite, delete, publish, or otherwise modify content.

3. Methodology

3.1 Assumptions

The main assumption is that pages with stronger observable opportunity signals can be useful candidates for human investigation. This is an operational assumption, not a causal claim.

The analysis treats search impressions, CTR, and average position as observational signals. They are not interpreted as proof that changing a page will produce a particular future outcome.

3.2 Features

The workflow used measurable content and performance signals. The main features included:

  • Search impressions
  • Click-through rate (CTR)
  • Average search position
  • Content age
  • Word count where available
  • Derived opportunity scores based on observed performance

The final action queue also contained interpretable components such as CTR opportunity and position opportunity.

3.3 Baseline

The Week-4 baseline deliberately used a transparent rule rather than a complex model. The baseline produced an action score and a single reason code for each eligible page.

A key reason code was:

LOW_CTR

This represented pages where the observed CTR signal suggested an opportunity for human review. The resulting score was used only to rank the queue.

3.4 Modeling approach

The Week-5 modeling work investigated a machine-learning approach using the same underlying performance signals and compared the model against the baseline rather than rewarding complexity by itself.

The modeling workflow emphasized interpretable features and an explicit validation design. The purpose was to determine whether the model provided measured evidence beyond the simple rule.

3.5 Validation design

The later validation audit specifically examined whether a conventional random split could give an overly optimistic view when records from the same client appear in both training and evaluation data.

A grouped-by-client validation design was therefore used as the more conservative evaluation perspective. This tests whether the learned relationship generalizes beyond pages belonging to the same client groups seen during training.

Interpretation: The grouped evaluation is treated as the more honest estimate for cross-client generalization. Differences between ordinary and grouped evaluation should be interpreted as evidence about generalization difficulty, not as evidence that the model is universally accurate.

3.6 Leakage checks

The feature audit considered whether variables contained future information or information derived directly from the outcome being evaluated.

The analysis specifically avoided future-window performance measures and label-derived inputs when constructing the decision-support features. The validation audit also reviewed the final feature set for variables that could leak information from the evaluation period.

This was an important part of the workflow because a feature can appear predictive while actually encoding information that would not be available at decision time.

4.4 Model versus baseline

The central comparison in the modeling work was designed to use the same data and evaluation split for the model and baseline. This prevents a difference in the evaluation population from being mistaken for a model improvement.

The project deliberately does not claim that the model is better simply because it is more complex. The appropriate conclusion depends on the measured evaluation metrics from the executed Week-5 notebook.

Decision-support conclusion: The workflow provides a reproducible way to rank content opportunities, but the evidence supports prioritization and investigation rather than an automatic claim of improved future SEO performance.

5. Limitations & Honest Framing

  • The dataset covers a limited reporting window, so the observed patterns may not represent longer-term seasonality.
  • The analysis is observational. It does not establish that changing a page will cause higher traffic, CTR, or search rankings.
  • Average position and CTR are correlated signals, so their relationship should not be interpreted as a causal mechanism.
  • Some content records do not have complete performance information, so availability flags matter when interpreting results.
  • Client grouping means that cross-client generalization is more demanding than evaluating pages from clients already represented in training data.
  • The ranked queue should be treated as a prioritization aid, not as an automated publishing or optimization system.

The strongest defensible framing is therefore: the analysis measured directional signals that can support human review and action prioritization.

6. Ranked Recommendations

The action playbook converts the measured signals into a practical review workflow.

Priority Action Reason
1 Prioritize for human review Investigate pages with a strong observed CTR opportunity before making content changes.
2 Inspect search positioning Review pages where search position suggests an opportunity but do not assume ranking improvement is guaranteed.
3 Check content context Use content characteristics and editorial context to determine whether the measured signal is actionable.
4 Re-check before action Confirm that the signal remains current before an editor acts.

Human review requirements

A human should inspect the page before any substantive change. The reviewer should check search intent, content quality, relevance, technical context, and whether the measured signal could have a non-content explanation.

What should NOT be automated

  • Automatic deletion of pages
  • Automatic publication of rewritten content
  • Automatic changes to important metadata without review
  • Automatic claims that an optimization will improve rankings
  • Automatic decisions based solely on the action score
